Phase D's FAIL was a script bug (this file's earlier `m.raw.read_encoder_value()`
does not exist on RawDriver; the real methods are `read_encoder`,
`read_angle_degrees`, `read_motor_status`). Fixed in `scripts/soak_v1.0_prep.py`
in commit 527beb4 and re-ran Phase D inline:

a single session produced zero transport contention.

## Earlier run (interrupted)

A first soak attempt at 22:14 ran 1293 clean moves in Phase B (~11 min) before
the USB-RS485 adapter physically dropped off the bus (USB device disappeared
from `lsusb` — likely a power glitch through a hub; the second run on a
direct port held 1400 moves over 10 min without issue).

That interrupted run uncovered one real library bug: `OSError(5, EIO)` from
pyserial was not wrapped in `CommTimeout`, so `except CommTimeout` did not
catch the device-disconnect case. Fixed in commit `0fb05f7` with 3 regression
tests (test_transport.py).
