## 1. Goal

Add multi-motor support on a single RS485 bus, promote the `motor.raw`
namespace from private to public, add a `mks-servo bus discover` CLI
command, and add opt-in profile write-through. End user code:

```python
from mks_servo import MotorBus

with MotorBus("/dev/ttyUSB0", baud=38400) as bus:
    wrist  = bus.add("./profiles/wrist.yaml")     # servo42d, addr=1
    elbow  = bus.add("./profiles/elbow.yaml")     # servo42d, addr=2
    wrist.write(45)
    elbow.write(90)
    print(f"wrist: {wrist.read()}, elbow: {elbow.read()}")
```

Plus the existing single-motor `Motor.from_profile("wrist")` keeps working.

## 2. Architecture changes

### 2.1 New layer: `SharedTransport`

Currently `RawDriver` constructs and owns its own `serial.Serial`. To support
multiple drivers on the same physical bus, the transport must be shareable.
`SharedTransport` wraps a `serial.Serial` + a `threading.Lock` and exposes
the same `transact()` semantics:

```
┌─ SharedTransport (mks_servo/transport.py) ────────────────────┐
│   Wraps serial.Serial + threading.Lock.                       │
│   transact_locked(addr, code, data, expect_payload_len, ...)  │
│   open() / close() / __enter__ / __exit__                     │
└───────────────────────────────────────────────────────────────┘
```

`RawDriver.__init__` gains an optional `transport: SharedTransport | None`
parameter:
- If `transport` is None: RawDriver creates and owns its own (current
  v0.1.0 behaviour — single motor on one bus).
- If `transport` is given: RawDriver delegates serial I/O to it. Multiple
  RawDrivers can share the same SharedTransport.

The existing module-level `transact(ser, ...)` function stays as-is for
backward compatibility within the codebase, but `SharedTransport.transact()`
is the new preferred entry.

### 2.2 New: `MotorBus`

```
┌─ MotorBus (mks_servo/bus.py) ─────────────────────────────────┐
│   Owns one SharedTransport.                                   │
│   add(profile) → Motor (sharing the transport, no own raw)    │
│   scan(addr_range=range(1,17)) → list[BusEntry]               │
│   __iter__, __len__, __contains__                             │
│   open()/close() lifecycle + context manager                  │
└───────────────────────────────────────────────────────────────┘
```

`MotorBus.add(profile)` constructs a `Motor` whose RawDriver shares the
bus's `SharedTransport`. Multiple `add()` calls produce independent
`Motor` instances bound to the same bus.

`MotorBus.__enter__` calls `open()`, which opens the serial transport.
`Motor.attach()` on a Motor that already owns its own transport is a
no-op for opening (transport is already shared and open). `Motor.attach()`
still applies the profile config to the driver.

### 2.3 Public `motor.raw` (Level 3 promoted)

In v0.1.0 the raw driver was at `motor._raw`. In v0.2.0 it becomes
`motor.raw` — the public Level 3 API. This is a **breaking change** for
any code that referenced `_raw`. Documented in CHANGELOG.

`motor._raw` no longer exists.

### 2.4 Opt-in profile write-through

```python
m = Motor.from_profile("wrist", auto_save=True)
m.work_current_ma = 2000   # writes to driver AND saves YAML
```

`auto_save=True` is opt-in. Default `False` preserves v0.1.0 behaviour
(in-memory profile changes only).

When enabled, every Level-1 setter that mutates the profile triggers a
`profile.save()` after the driver write succeeds.

### 2.5 New: `Profile.snapshot_from(motor)`

```python
prof = motor.profile
prof.snapshot_from(motor)    # reads driver state, updates config: section
prof.save()                   # persist
```

Reads `motor.raw.read_all_config()` and updates the profile's `config:`
section (mode, microsteps, work_current_ma, hold_current_pct, direction).
Does NOT update `limits`, `mechanical`, or `characterization` (those are
not knowable from the driver). Does NOT auto-save.

## 4. API specifications

### 4.1 `SharedTransport`

```python
class SharedTransport:
    """Wraps a serial.Serial + a Lock. Multiple RawDrivers can share one."""

    def __init__(self, port: str, baud: int = 38400, timeout: float = 3.0): ...

    def open(self) -> None: ...
    def close(self) -> None: ...
    def __enter__(self) -> "SharedTransport": ...
    def __exit__(self, *_) -> None: ...

    def transact(self, *, addr: int, code: int, data: bytes,
                 expect_payload_len: int) -> tuple[int, int, bytes]:
        """Sequential transact() under the lock. Forwards to the existing
        module-level transact() function with self._ser."""
```

### 4.2 `RawDriver` constructor change

```python
class RawDriver:
    def __init__(self, port: str = None, baud: int = 38400,
                 addr: int = 1, timeout: float = 0.5,
                 *,
                 transport: SharedTransport | None = None) -> None:
        """If transport is given, port/baud/timeout are ignored — the driver
        does not own the transport, and `open()`/`close()` become no-ops."""
```

If `transport` is provided, `RawDriver.open()` becomes a no-op (the bus
owns the lifecycle). Same for `close()`.

The `_txn()` helper now calls `self._transport.transact(...)` instead of
the bare `transact(self._ser, ...)`. `self._transport` is either the
externally-provided one or an internal one created lazily on `open()`.

### 4.3 `MotorBus`

```python
class MotorBus:
    """Multi-motor coordinator on a single RS485 transport."""

    def __init__(self, port: str, baud: int = 38400, timeout: float = 3.0): ...

    def open(self) -> None: ...
    def close(self) -> None: ...
    def __enter__(self) -> "MotorBus": self.open(); return self
    def __exit__(self, *_) -> None: self.close()

    def add(self, profile: str | Path | Profile) -> Motor:
        """Construct a Motor whose RawDriver shares this bus's transport.
        The Motor is auto-attached (config applied to driver). Returns the Motor."""

    def remove(self, motor: Motor) -> None:
        """Detach the motor from the bus and from this object's tracking."""

    def scan(self, addr_range: range = range(1, 17)) -> list["BusEntry"]:
        """Probe each address; return a list of detected drivers."""

    def __iter__(self): return iter(self._motors)
    def __len__(self) -> int: return len(self._motors)
    def __contains__(self, motor: Motor) -> bool: return motor in self._motors
```

```python
@dataclass
class BusEntry:
    """A discovered driver on the bus."""
    addr: int
    model: str            # "servo42d" (only model in v0.2.0)
    config: dict          # output of read_all_config()
    profile: Profile | None = None  # populated only if scan(create_profiles=True)
```

`scan()` for each address in the range:
1. Creates a temporary `RawDriver(transport=self._transport, addr=addr)`
2. Tries `read_all_config()` with a short timeout (1s).
3. On success: builds a `BusEntry`.
4. On `CommTimeout`: skips silently (no driver at that address).
5. Returns the list.

Optional `scan(create_profiles=True, output_dir=Path("./profiles"))`:
also constructs a `Profile.from_driver(...)` and saves under
`<output_dir>/motor_<addr>.yaml`.

### 4.4 `motor.raw` public

In `Motor`:
- `motor.raw` returns the `RawDriver` instance.
- Accessing `motor._raw` raises `AttributeError` (we don't keep a deprecated alias).
- All internal references inside `motor.py` are updated (`self._raw` → `self.raw`).

### 4.5 `Motor` `auto_save` flag

```python
class Motor:
    def __init__(self, profile, *, raw=None, auto_save: bool = False): ...
```

When `auto_save=True`:
- After every successful Level-1 setter (work_current_ma, microsteps, mode,
  direction, hold_current_pct, position_limits, speed_limit_rpm), the profile
  is saved (`profile.save()`).
- After successful `set_origin()`, `calibrate()`, `restart()`, the profile
  is saved.
- `auto_save` does NOT trigger on every `write()` (that would be far too
  noisy — `write` doesn't mutate config).

If `profile.path is None` (template-loaded) and `auto_save=True`, it's a
silent no-op for save (warning logged once).

### 4.6 `Profile.snapshot_from(motor)`

Reads the driver via `motor.raw.read_all_config()` and updates the
profile's `config:` section. The implementation reuses the same key
translation map as `Profile.from_driver` (already determined in v0.1.0
Task 9: `current_ma`, `subdivision`, `dir_cw`, `hold_current_pct_idx`,
`baud_code`, `mode`).

```python
def snapshot_from(self, motor) -> None:
    """Read motor's driver state, overwrite this profile's `config:` and
    `driver.slave_addr`. Does NOT save (caller invokes `save()`)."""
```

## 5. CLI specification

### 5.1 New: `bus` subgroup

```bash
mks-servo bus discover --port /dev/ttyUSB0 [--range 1-16] [--baud 38400]
mks-servo bus discover --port /dev/ttyUSB0 --create-profiles [--out ./profiles]
```

Behaviour:
- Probes addresses in the range.
- For each found driver, prints: `addr=N: servo42d, mode=<mode>, current=<ma> mA, subdiv=<n>`.
- If `--create-profiles`: saves `<out>/motor_<addr>.yaml` for each, refusing
  overwrite without `--force`.

### 5.2 Existing `profile` subcommands

Unchanged.

## 8. Out of scope (v0.2.0)

- Velocity mode on `Motor` (deferred to v0.3+).
- `motor.advanced.*`, `motor.homing.*`, `motor.io.*` namespaces (v0.3).
- `characterize` CLI command (v0.3).
- ROS 2 nodes (never).
- Async API (never).
- Real concurrency optimisations (RS485 is half-duplex; sequential is correct).

## 9. Acceptance criteria

v0.2.0 is "done" when ALL of:

1. `from mks_servo import MotorBus` works.
2. `MotorBus(port).__enter__` opens transport; `bus.add(profile)` returns a Motor.
3. `motor.raw.read_all_config()` works (public Level 3).
4. `motor._raw` raises AttributeError (alias gone).
5. `bus.scan(range(1,17))` returns BusEntry list (mocked test passes).
6. `mks-servo bus discover --port X` prints discovered drivers.
7. `Profile.snapshot_from(motor)` populates config from driver.
8. `Motor(profile, auto_save=True)` saves YAML after each Level-1 setter.
9. All v0.1.0 tests still pass after `_raw` → `raw` rename.
10. Examples in `examples/` parse and `--help` (where applicable).
11. Updated CHANGELOG.md mentions the breaking change.

## 10. Risks and mitigations

| Risk | Mitigation |
|---|---|
| Renaming `_raw` → `raw` breaks v0.1.0 users | Document loudly in CHANGELOG; pre-v1.0 contract allows breaking changes |
| `bus.scan` floods serial with timeouts | Use 1s timeout for scans (vs default 3s for normal ops) |
| Multiple Motors race the transport | `SharedTransport.transact_locked` serialises every transaction with `threading.Lock` |
| `auto_save` writes too often | Only triggered by config-mutating setters, not by `write()` |
