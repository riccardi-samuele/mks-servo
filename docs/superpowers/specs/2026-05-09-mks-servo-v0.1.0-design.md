# mks-servo v0.1.0 — Design Specification

**Status:** Approved design (ready for implementation plan).
**Date:** 2026-05-09
**Owner:** Samuele
**Phase:** Foundation single-motor (first phase of `mks-servo` roadmap).
**Scope reference:** see `2026-05-09-mks-servo-vision.md`.

---

## 1. Goal

Refactor the existing `mks_servo/` codebase into the foundation of a
profile-driven Python library. Single motor only, Level 0 + Level 1 API,
YAML profile system, minimal CLI. After v0.1.0, a user should be able to:

```python
from mks_servo import Motor

with Motor.from_profile("wrist") as m:
    m.set_origin()
    m.position_limits = (-90, 90)
    m.write(45, rpm=300)
    print(m.read())
```

…with a profile YAML file produced either by introspecting a connected
driver or by copying a built-in template.

## 2. Architecture

### 2.1 Module boundaries

```
USER CODE
   │  motor = Motor.from_profile("wrist.yaml")
   │  motor.attach(); motor.write(90)
   ▼
┌─ Motor (mks_servo/motor.py) ─────────────────────────────┐

└──────────────┬───────────────────────────────────────────┘
               │ uses
               ▼
┌─ Profile (mks_servo/profile.py) ─────────────────────────┐
```

### 2.3 Why `RawDriver` is private in v0.1.0

`Motor` calls `RawDriver` internally via `motor._raw`. The underscore signals
"unstable, may move." In v0.2.0 it becomes `motor.raw` (public, Level 3
official). Keeping it private now buys flexibility to refactor opcode
signatures during v0.1.0 development.

### 2.4 Naming

- `Motor` (not `MKSServoMotor` or `Servo42DMotor`): generic — model is
  carried by the profile (`driver.model`). Future SERVO57D support won't
  require a rename.
- `RawDriver` (not `Driver` or `MKSServo42D`): "raw" emphasizes Level-3
  semantics. The model-specific class lives at `mks_servo.raw.Servo42DRaw`
  (so a `Servo57DRaw` can join later without ambiguity); `RawDriver` is the
  current alias used by `Motor`.

## 3. Profile schema (`schema_version: 1`)

### 3.1 Full schema

```yaml
schema_version: 1                    # REQUIRED
id: wrist                            # REQUIRED, used as filename stem
description: ""                      # optional, free-form
created_at: 2026-05-09T14:30:00Z     # ISO-8601 UTC
updated_at: 2026-05-09T15:45:00Z     # ISO-8601 UTC, auto-updated on save

driver:                              # REQUIRED
  model: servo42d                    # servo42d (only one supported in v0.1.0)
  firmware_min: "1.0.6"              # advisory; warning if driver firmware lower
  slave_addr: 1                      # 1..247

transport:                           # OPTIONAL — can be supplied at runtime
  port: null                         # null | "/dev/ttyUSB0"
  baud: 38400                        # 9600 | 19200 | 38400 | 57600 | 115200
  timeout_s: 3.0                     # > 0

config:                              # parameters written to driver on attach()
  mode: SR_vFOC                      # SR_OPEN | SR_CLOSE | SR_vFOC
  microsteps: 16                     # 1..256
  work_current_ma: 1500              # 0..3000
  hold_current_pct: 50               # 10..90, step 10
  direction: CW                      # CW | CCW

limits:                              # software limits applied by Motor
  position:
    min_deg: null                    # null | float (output-axis degrees)
    max_deg: null                    # null | float
    on_violation: reject             # reject | clamp | warn
  speed:
    max_rpm_safe: null               # null | int
    on_violation: clamp
  current:
    max_ma: 3000                     # hard cap; always enforced as `reject`
                                     # (no on_violation field — current cannot be safely clamped)

origin:
  set_in_firmware: true              # if true, set_origin() uses cmd 0x92
  encoder_offset_counts: 0           # used when set_in_firmware=false

mechanical:
  motor_model: ""                    # free-form, e.g., "NEMA17"
  full_steps_per_rev: 200
  gear_ratio: 1.0                    # output_deg = motor_deg / gear_ratio

characterization:                    # populated by tests; everything optional
  last_calibrated: null              # ISO-8601 UTC
  precision:
    sigma_deg: null
    peak_deg: null
  speed:
    max_measured_rpm: null
    voltage_v: null
```

### 3.2 Validation rules

A profile is valid iff:

- `schema_version == 1`
- `id` is a non-empty string of `[a-zA-Z0-9_-]`
- `driver.model in {"servo42d"}` (v0.1.0)
- `driver.slave_addr` in `1..247`
- `transport.baud` in the enum set above
- `config.mode` in `{SR_OPEN, SR_CLOSE, SR_vFOC}`
- `config.microsteps` in `1..256`
- `config.work_current_ma` in `0..config.current.max_ma` (cross-check)
- `config.hold_current_pct` in `10..90` and divisible by 10
- `config.direction` in `{CW, CCW}`
- For `limits.position` and `limits.speed`: if `min`/`max` (or `max_rpm_safe`)
  is not null, the other must be too where applicable, and `min < max`
- `limits.position.on_violation` and `limits.speed.on_violation` in
  `{reject, clamp, warn}`
- `limits.current` has no `on_violation` field — violations always raise
  `LimitExceeded`
- `mechanical.gear_ratio > 0`
- `mechanical.full_steps_per_rev > 0`

`Profile.validate()` raises `ProfileError` listing all violations (collect
all, don't fail-fast).

### 3.3 Profile lookup

`Profile.load(name)` searches in this order:

1. If `name` ends with `.yaml` or `.yml` and is a path: load that path.
2. `./profiles/<name>.yaml` (project)
3. `~/.config/mks-servo/profiles/<name>.yaml` (user)
4. `mks_servo/profiles/_templates/<name>.yaml` (built-in templates)

If found in 4 and the user calls `Profile.load("nema17-bipolar-2A")`, the
returned `Profile` object has `path=None` (template, no auto-save target);
calling `.save()` raises `ProfileError("template profile must be saved with explicit path")`.

### 3.4 Profile creation modes

```python
# (a) From scratch
prof = Profile(id="wrist", driver_model="servo42d", slave_addr=1)

# (b) From template
prof = Profile.from_template("nema17-bipolar-2A", id="wrist")

# (c) From running driver (introspection)
# The caller instantiates a RawDriver directly (Profile does not own transport).
raw = RawDriver(port="/dev/ttyUSB0", baud=38400, addr=1)
prof = Profile.from_driver(raw, id="wrist")    # populates `config:` from cmd 0x47/0x48
```

`from_driver` reads the following from the connected driver and populates
the corresponding profile fields:

| Profile field | Source opcode | Field within response |
|---|---|---|
| `config.mode` | cmd 0x47 (read all config) | byte offset for mode |
| `config.work_current_ma` | cmd 0x47 | current bytes |
| `config.microsteps` | cmd 0x47 | subdivision byte |
| `config.hold_current_pct` | cmd 0x47 | holding current pct byte |
| `config.direction` | cmd 0x47 | direction bit |
| `driver.slave_addr` | cmd 0x47 | address byte |
| `transport.baud` | cmd 0x47 | baud enum |

(Exact byte offsets verified against firmware V1.0.6 manual, locked into
implementation tests.)

`limits` and `mechanical` and `characterization` are NOT populated by
`from_driver` — they are not knowable from the driver. They get sane
defaults (limits all null, gear_ratio=1.0, characterization empty).

### 3.4.1 Profile object attributes

Every `Profile` carries:

- `profile.path` — the resolved file path it was loaded from, or `None` if
  the profile was loaded from a built-in template, constructed in memory,
  or returned by `from_driver`.
- `profile.config`, `profile.limits`, `profile.driver`, ... — typed
  attribute access matching the YAML structure.

### 3.5 Save semantics

- `profile.save()` writes back to `profile.path`. Round-trip preserves
  comments and ordering (ruamel.yaml).
- `profile.save("/new/path.yaml")` writes to a new path; `profile.path`
  is updated.
- `updated_at` is automatically refreshed on each save.
- If the profile was loaded from a built-in template (`path=None`), `save()`
  without an explicit path raises `ProfileError`.

## 4. API specification

### 4.1 `Motor` — Level 0

```python
class Motor:
    @classmethod
    def from_profile(cls, profile: str | Path | Profile, *,
                     port: str | None = None) -> "Motor":
        """Construct a Motor from a profile.
        - If `profile` is a string/Path: passed to Profile.load().
        - If `profile` is a Profile: used directly.
        - `port` overrides profile.transport.port (useful when profile has port=null)."""

    def attach(self) -> None:
        """Open the serial transport, instantiate RawDriver, write profile.config
        to the driver, verify the driver responds. Idempotent.
        Raises: CommTimeout, ProfileError (firmware version mismatch), MotorFault."""

    def detach(self) -> None:
        """Disable the motor, close the serial transport. Idempotent.
        Always safe to call. Called automatically by __exit__."""

    def __enter__(self) -> "Motor": self.attach(); return self
    def __exit__(self, *_) -> None: self.detach()

    def write(self, angle_deg: float, *,
              rpm: int | None = None,
              acc: int | None = None,
              blocking: bool = True,
              timeout: float | None = None) -> None:
        """Move to absolute angle (output-axis degrees, gear_ratio applied).
        - rpm None → uses default (300 if not set elsewhere); checked vs limits.speed.
        - acc None → uses default (50); range 1..255.
        - blocking True → calls wait_until_idle(timeout) before returning.
        Raises: LimitExceeded, MotorNotAttached, CommTimeout."""

    def read(self) -> float:
        """Current absolute angle in output-axis degrees (encoder cumulative,
        with gear_ratio and origin offset applied)."""

    def error(self) -> float:
        """Current following error (encoder - commanded), in output-axis degrees."""

    def is_moving(self) -> bool:
        """True if the motor is currently executing a move."""

    def emergency_stop(self) -> None:
        """Immediate stop (cmd 0xF7) followed by disable. Best-effort, no
        exceptions raised. Safe to call from signal handlers."""
```

### 4.2 `Motor` — Level 1 properties

```python
# Read+write (write goes to driver immediately)
motor.work_current_ma:   int            # 0..profile.limits.current.max_ma
motor.hold_current_pct:  int            # 10..90, step 10
motor.microsteps:        int            # 1..256
motor.mode:              WorkMode       # SETTER triggers automatic restart()
motor.direction:         Direction      # CW | CCW

# Runtime-only limits (in-memory, NOT auto-saved)
motor.position_limits: tuple[float | None, float | None]
motor.speed_limit_rpm: int | None

# Read-only
motor.position_counts:   int            # raw encoder cumulative
motor.speed_rpm:         int            # signed
motor.enabled:           bool
motor.status:            MotorStatus
motor.profile:           Profile        # the underlying Profile object
motor.model:             str            # profile.driver.model
```

### 4.3 `Motor` — Level 1 additional methods

```python
def set_origin(self, *, soft: bool = False) -> None:
    """Set the current position as the zero.
    - soft=False (default): cmd 0x92, persists in driver flash.
    - soft=True: stores offset in profile, no flash write.
      Profile NOT auto-saved; call profile.save() yourself."""

def move_relative(self, delta_deg: float, *,
                  rpm: int | None = None, acc: int | None = None,
                  blocking: bool = True, timeout: float | None = None) -> None:
    """Move by a delta (output-axis degrees). Same params and limits as write()."""

def enable(self, state: bool = True) -> None:
    """Enable/disable the motor (cmd 0xF3)."""

def disable(self) -> None:
    """Alias for enable(False)."""

def wait_until_idle(self, timeout: float | None = None) -> None:
    """Block until status indicates motion stopped, or raise CommTimeout."""

def calibrate(self, *,
              current_ma: int = 3000,
              timeout: float = 30.0) -> None:
    """Run the FOC calibration sequence with the delays found via HIL:
    enable(False) → set_work_mode(SR_vFOC) → set_subdivision(16) →
    set_work_current_ma(current_ma) → 500ms between each →
    cmd 0x80 → poll status until done.
    On success: profile.characterization.last_calibrated updated;
                profile NOT auto-saved.
    On failure: restore previous current; raise CalibrationFailed."""

def restart(self) -> None:
    """Restart the driver (cmd 0x41). Re-runs attach() internally."""

def restore_defaults(self) -> None:
    """Reset driver to factory defaults (cmd 0x3F). Use with care."""
```

### 4.4 Limit enforcement in `write()` and `move_relative()`

The order of operations:

```
1. Compute target angle in output-axis degrees (already in deg, identity).
2. Check `motor.position_limits` (NOT profile.limits.position — runtime takes
   precedence over profile if explicitly set).
   - If both None: skip check.
   - If outside: apply on_violation policy from profile.limits.position.on_violation.
3. Compute effective rpm (caller arg → motor.speed_limit_rpm → profile default).
4. Check rpm against motor.speed_limit_rpm (or profile.limits.speed.max_rpm_safe
   if speed_limit_rpm is None).
   - If outside: apply on_violation policy.
5. Convert angle → encoder counts:
     counts = round(angle_deg * 0x4000 / 360.0 * gear_ratio) - origin_offset
6. Call _raw.move_absolute_axis(counts=..., rpm=..., acc=...).
7. If blocking: _raw.wait_until_idle(timeout).
```

Current limit (`limits.current`) is enforced when `motor.work_current_ma`
property is set — `LimitExceeded` is always raised on violation, regardless
of `on_violation` (current is the one limit you can't clamp safely).

### 4.5 Exceptions

```python
# Existing in mks_servo.exceptions:
class MKSError(Exception): ...
class CommTimeout(MKSError): ...
class ChecksumError(MKSError): ...
class ProtocolError(MKSError): ...
class MotorFault(MKSError): ...
class CalibrationFailed(MKSError): ...

# NEW in v0.1.0:
class ProfileError(MKSError):
    """Schema invalid, file corrupt, range out of bounds, unknown schema_version."""
    def __init__(self, message: str, *, violations: list[str] | None = None): ...

class LimitExceeded(MKSError):
    """A command was rejected because it violated a software limit."""
    kind: Literal["position", "speed", "current"]
    value: float
    limit: float
    def __init__(self, kind, value, limit, message=None): ...

class MotorNotAttached(MKSError):
    """A method requiring an open transport was called before attach()."""
```

## 5. CLI specification

Entry point: `mks-servo` (registered via `pyproject.toml`).

### 5.1 Subcommands in v0.1.0

```bash
mks-servo profile from-driver --port PORT --addr ADDR --as ID [--out PATH]
mks-servo profile from-template TEMPLATE --as ID [--out PATH]
mks-servo profile validate ID_OR_PATH
mks-servo profile show ID_OR_PATH [--section SECTION]
```

### 5.2 Behavior

- `from-driver`: opens serial, reads driver config, writes
  `./profiles/<id>.yaml` (or `--out` if specified). Refuses to overwrite
  existing file unless `--force`.
- `from-template`: copies a built-in template, sets `id` and `created_at`,
  writes `./profiles/<id>.yaml`.
- `validate`: loads the profile and runs `Profile.validate()`. Prints
  violations or "OK". Exit code 0 on valid, 1 on invalid.
- `show`: prints the profile YAML, optionally limited to one section
  (e.g., `--section limits`).

### 5.3 Exit codes

- 0: success
- 1: validation failure or expected error (file not found, etc.)
- 2: CLI usage error (handled by click)

## 6. Testing strategy

### 6.1 Unit tests (mocked serial, no hardware)

Target: ~80% line coverage of `motor.py`, `profile.py`, `cli/`. Coverage
not enforced by CI (kept simple); checked occasionally with `pytest-cov`
locally.

Required test files:

- `tests/test_motor.py`
  - `attach()` calls into RawDriver and writes config
  - `attach()` is idempotent
  - `write()` passes angle → counts conversion correctly
  - `write()` rejects out-of-position-limit with `LimitExceeded`
  - `write()` clamps speed when `on_violation=clamp`
  - `write()` warns and proceeds when `on_violation=warn`
  - `mode` setter triggers `restart()`
  - `set_origin()` calls cmd 0x92 when soft=False
  - `set_origin(soft=True)` updates profile.origin.encoder_offset_counts
  - `emergency_stop()` does not raise on transport errors
  - Context manager calls `detach()` on exit and on exception
  - `MotorNotAttached` raised when calling write/read before attach
- `tests/test_profile.py`
  - Valid profile round-trip preserves all sections
  - Invalid profile reports all violations (not just first)
  - Lookup order: project → user → templates
  - `from_template` produces a valid profile
  - `from_driver` populates `config:` from mocked raw
  - Save updates `updated_at`
  - Save preserves user comments
  - Saving a template-loaded profile without explicit path raises
  - Schema version 0 / 2 raises `ProfileError`
- `tests/test_limits.py`
  - All three policies (reject/clamp/warn) for position, speed, current
  - Runtime `motor.position_limits` overrides profile values
  - Disabling limits via `(None, None)` works
- `tests/test_cli.py`
  - `from-driver` end-to-end with mocked serial
  - `from-template` writes correct YAML
  - `validate` exit codes
  - `show --section` filtering

### 6.2 HIL smoke tests (require hardware, marker `hil`)

Run manually before each release. ~3 minutes total wall time.

- `tests/hil/test_smoke_motor.py`: attach, write 0/+45/-45, read, detach.
- `tests/hil/test_calibrate.py`: full calibration sequence; assert
  `last_calibrated` populated.
- `tests/hil/test_set_origin.py`: set_origin firmware + soft variants.

### 6.3 Benchmark migration

Each existing benchmark script (`01_smoke.py`, `02_precision.py`,
`03_speed.py`, `04_persistence.py`) is migrated to use `Motor` as the
primary API. Where a benchmark needs Level-3 functionality not exposed by
`Motor` v0.1.0 (e.g., velocity-mode commands in `03_speed.py`'s S1/S2/S3,
raw config reads in `04_persistence.py`'s C1), the script may explicitly
descend to `motor._raw.<method>()`. This is acceptable for internal
characterization scripts and is precisely what `_raw` exists for in v0.1.0
— the underscore signals "you know what you're doing."

Output CSV columns and PNG plots remain identical to pre-migration
baselines (regression-checked manually).

This forces the `Motor` surface to be at least sufficient for the
characterization workflow — driving the API design from real use, while
not over-promising what Level 0/1 can do alone.

### 6.4 What is NOT tested in v0.1.0

- Coverage threshold enforcement (over-engineering)
- Property-based tests (over-engineering)
- Multi-motor scenarios (out of v0.1.0 scope)
- Async behavior (no async API in v0.1.0)

## 11. Risks and mitigations

| Risk | Mitigation |
|---|---|
| Refactor in-place breaks running benchmarks during transition | Each plan task migrates one benchmark + the corresponding library piece together; benchmarks always green |
| `from_driver` introspection gets the byte offsets wrong | Locked into unit tests using captured frame data from real driver (already characterized in HIL session) |
| `mode` setter auto-restart causes surprises | Documented in docstring; first paragraph highlights it; warning logged |
| Profile YAML format collides with future schema v2 | `schema_version` field is mandatory; loader rejects unknown versions explicitly |
| ruamel.yaml has a different round-trip behavior on some systems | Use `YAML(typ="rt")` explicitly; pin minor version in pyproject |
| Profile lookup order surprises users (loads template instead of project profile) | `Profile.load()` returns a `path` attribute; CLI `show` always prints which path was resolved |
